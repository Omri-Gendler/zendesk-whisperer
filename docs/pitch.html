Zendesk Whisperer

A copilot for support agents. It reads the ticket from the screen and writes a summary plus drafts — without the guest thread leaving this computer.

The problem

Long tickets. Several parties. Expensive time.

  • The agent reads guest, hotel, supplier, and internal notes in one thread.
  • They need Hebrew to the customer and English to the hotel — in a consistent tone.
  • Every minute here is a minute another case is not closed.

The product in one line

A Chrome side panel on top of the Zendesk they already use.

Not a Zendesk app. Not a new screen. The agent stays on the ticket, clicks Generate, and gets text ready to copy.

What the agent gets

Our internal-note summary, and drafts by party.

Order numberFrom the ticket, not a guess
Supplier nameExpedia, Hotelbeds, hotel
Issue descriptionWhat the guest actually asked
Actions takenWhat already happened in the thread
Follow-upWhat is blocking, who we wait on
DraftsGuest · hotel · supplier · copy only

Control

Hebrew only where you mark it.

Four chips. Mark them — the selection is visible. You can mark before Generate.

Guest Hotel Supplier Summary

Default: Hebrew to the guest, English to hotel and supplier. No EL AL footer — Zendesk already adds it.

Privacy

The ticket does not leave the machine.

  • No OpenAI. No cloud Gemini. No provider key in the extension.
  • No Zendesk API — only what is on the screen.
  • Chrome on-device model, or Ollama on this computer, or built-in rules.

A remote model URL is rejected. That fits EL AL Travel guest tickets.

How it runs

Screen → panel → local model → Copy.

Zendesk ticket → Read from the page → Generate locally → Copy

Switching tickets clears the previous summary. No mix-up between cases.

What we leave out on purpose

The agent stays accountable.

  • We do not send on the agent’s behalf.
  • We do not write into the Zendesk composer.
  • We do not store tickets in the cloud.
  • No public Chrome Web Store — internal extension.

Next step

Two minutes on a live ticket. Then a pilot.

  • Shared demo on a real case.
  • Pilot with 2–3 agents.
  • Measure: time to a summary, and whether the draft is sent almost as-is.
